# 翻译质量、划词纠错与高速兜底验收（0.2.2）

日期：2026-11-03。扩展 `0.2.2`，后台 `0.2.2-alignment`，协议 v2。延续 0.2.1 的整句翻译与占位符保护，进一步修复用户给出的 `concerns → 逗号` 错配，接入 B5 右键菜单、浏览器内置翻译和默认关闭的 Google 网页兜底。

## 用户问题与结果

| 复现 | 修正后的行为 |
|---|---|
| Phonetics 六句段落选择 `concerns`，中文只亮逗号 | 首次和再次选择均对应 `研究`；反向选择 `研究` 只对应 `concerns` |
| 同段 `acoustic` 可能吞掉多个并列术语 | `acoustic ↔ 声学`，`auditory → 听觉` |
| 模型已加载但该段尚未算完，280ms 后返回空结果并永久留在前端缓存 | 每个未缓存段落最多等待真实计算 5 秒，完成即返回；缓存命中仍立即返回 |
| 带链接的本地模型译文被短词片段拼接破坏语序 | 优先完整语境翻译，再用精确词组、真实词典义项和本机语义锚点恢复标签 |
| 免费预算耗尽，快速档没有可用服务 | 同次请求继续尝试浏览器内置翻译、本地模型和用户已开启的可选后备 |
| B5 图片/PDF 前端有功能，后台缺右键入口 | 图片菜单发送 `translate-image` 给正确 frame；PDF 菜单打开本扩展双栏阅读器 |

本次划词问题不是单纯的模型译质：0.2.1 曾为补齐句子高亮而按位置给未知词配链接，语序变化后就产生了 `concerns → ，`。现在彻底删除这种补齐，禁止实词连到标点；真实语义证据和词典消歧决定链接，无法确认的词保持未连接。不会通过把整句话画满来掩盖错误。

## 翻译与格式

继续使用本机 Hy-MT2-1.8B Q4_K_M / llama.cpp，未换大模型或新增显存需求。默认采样参数、用户提示词设置保留。llama.cpp 适配器为 1.0.3，之前的版本缓存已失效，用户手动译文记忆保留。

整句恢复路径只把 `<gN>` 格式区间和 `<xN/>` 原子占位符恢复到真实译文，链接地址、代码等原内容由前端保留；数量、平衡、嵌套及交叉区间继续严格校验。原子随机标记逐项核对，不把代码发给模型重新编写。无法可靠恢复时继续安全降级或换服务，不返回未经校验的结构。

此前定义句实测：

> 机器翻译是利用计算技术将文本或语音从一种语言转换为另一种语言的过程，其中需要考虑两种语言的语境、习语和实际用法等细微差别。

相比之前“来自一个的文本或语音…另一方面”的短片段拼接，句义与语序明显改善。它仍是 1.8B 模型，不能保证所有多义词和专业术语都正确。重复长段可能被模型去重，格式压力通过不等于无漏译质量通过。实现与真实样例见 [TRANSLATION-QUALITY.md](TRANSLATION-QUALITY.md)。

## 划词、划句的实际边界

用户给出的 Wikipedia Phonetics 原段共六句、九个链接。真实本地翻译加真实 E5 WASM 对齐的严格浏览器回归八项通过。首次 `concerns → 研究` 等待 351ms，热词约 3–10ms；这些是已缓存权重的小样本，不是首次网络下载或 P50 基准。完整来源、断言与截图说明见 [PHONETICS-BROWSER-REGRESSION.md](PHONETICS-BROWSER-REGRESSION.md)。

对齐按句/窗口计算并限制在对应句内，选择一句会显示该句有证据的对应词组，不越到邻句；不能保证每个虚词都被填满。两个 Phonetics 真实译文的目标字符覆盖约 87%/93%，这些空缺保留。前端固定绘制的整段浅底色也仍保留；更明显的强高亮才是本轮修正的精确对应。首次模型下载超过 5 秒、模型不可用或词义不确定时，未知词可能没有强高亮。

算法、缓存时序、词典消歧、CPU 样例及保守降级见 [ALIGNMENT-QUALITY.md](ALIGNMENT-QUALITY.md)。前端缓存首次 Promise 的做法未改；后端此次延长每段等待并删除错误位置链接，避免把一个尚未完成的结果当作永久对齐。

## 浏览器内置翻译与调度

默认启用「浏览器内置翻译（Chrome / Edge）」并放入高速档，实际使用前检查该语言对是否已准备。首次点击现有的「保存并测试」，需要下载时会打开后端提供的可见准备页；用户在该页真实点击下载后，隐藏窗口即可在本机运行。健康探测不打开页面或伪造下载手势。

已在独立 Edge 156 中真实下载 en→zh 语言包，验证隐藏 Window 的原生翻译，以及后台 `chrome.i18n.detectLanguage` 可靠识别后转交原生模型的自动语言链路。Native LanguageDetector 在此机器不可用，因此使用浏览器扩展本身的 CLD 检测；检测不可靠或混语时换其他服务，不猜成英语。独立测试资料下载成功不代表日常 Edge 资料已准备。

按用户后续第 21 节建议，快速档默认依次使用已开启且可用的内置翻译、原有官方服务、本地；精确档保留本地优先于内置。只有上述可用官方/本机服务都未成功，且用户在设置明确开启，Google 网页接口才作为快速档最后后备。Google 在独立「非官方」分组，默认关闭、最低权重，固定单并发、每五秒一次；429 持久暂停，重启不自动恢复。细节、使用步骤和验证见 [TRANSLATION-FALLBACK.md](TRANSLATION-FALLBACK.md)、[BROWSER-TRANSLATOR.md](BROWSER-TRANSLATOR.md)。

有后备可用时翻译继续进行。所有服务都不可用时仍会返回真实错误，不能承诺断网且本地模型关闭时不断译。
