日期：2026-11-04。实际项目为 `项目根目录`，正式扩展目录为 `.output\chrome-mv3`。本轮保持前端、共享协议、假后端和 `wxt.config.ts` 不变；同步过程逐文件保护并校验。最终测试结果与包摘要在本页末尾登记。

## 已实现

1. DeepL 1.0.2 的翻译与用量查询均根据已去除两端空白的密钥后缀选主机；`:fx` 为 Free，其他为正式 API。字段名为“API 密钥”，服务名为“DeepL API”。不做失败后向另一主机试发密钥。
2. 官方确认 Developer 为总计 100 万字符、不重置；旧 Free 为每月 50 万。展示写明两种规则；实际 `/v2/usage` 的账户上限与用量优先。显式本地预算另算，未知账期不按日历月补额，官方零额不能被本地无限预算绕过。账户状态沿用既有 `cycle` 显示字段。
3. 缺少 `<xN/>` 时本地按原文相对位置、同父组及存留锚点补回；仅在完整结构重新校验成功后交付，既有译文不丢掉、不额外推理。远程 gateway 0.2.3 同步采用相同算法。
4. 输入、输出、缓存及人工记忆保留 Unicode 原字节；组合字素、辅助平面数学字母、斜体 h 和普通字符不混用。未修改模型权重或采样参数。
5. 新手指引涉及的 `-Cpu`、`-Port`、runtime 路径、`/health` 和模型 SHA 保持一致；未来变更需同步交接。

## 关键实现边界

- DeepL 官方账户计量与用户本地日/月预算是两层独立预留，在实际 HTTP 发送时一并校验和提交。账户状态和发送日志持久保存，切换密钥隔离等待批次、探测结果和在途请求状态；明文密钥不进入普通存储。
- `/usage` 没有套餐标识，账户上限可能包含付费套餐与成本控制，不能当成“免费字符数”。官方统计可能滞后；探测期间本机新增发送保守计入，下一次有效探测校正。key 级更低限制仍由上游 456 触发已有降级。
- 位置恢复是安全结构内的启发式估计。语序大幅变化时，不保证公式处于精确语义位置；坏组、额外/重复标记、跨组错位、空正文和无法判断的结构仍走原错误处理。模型自身可能改变数学字母；后端不做 Unicode 归一化不等于模型质量保证。
- 新缓存版本只影响带 `<xN/>` 的自动译文。普通段落缓存不因内部密钥配置代号变化而失效；人工记忆继续严格验证格式。
- DeepL 使用合成密钥与官方响应合约回放，未读取用户 DeepL 账户或消耗计费额度。真实模型测试仅用合成文本与临时浏览器，不涉及用户网页和论文正文。

真实模型采用独立 `127.0.0.1:8083`、6 路并行、同一 Hy-MT2-1.8B Q4_K_M 文件。为稳定覆盖漏标缺陷，测试代理只删除真实生成结果中的 `<xN/>`，保留其他生成字节；恢复结果必须与去掉标记的真实译文逐字相同。这是故障注入验收，不是声称本次模型自然漏标。实际结果：

```text
原文：With 𝑁 samples, compute <x0/> first, then check <x1/>. Keep ℎ unchanged.
恢复：使用 𝑁个样本，先计算<x0/> ，然后检查 <x1/>。保持 ℎ不变。
```

该样本只请求模型一次；第二次命中修复后的缓存。流式回归的首段预览比最终结果早约 354ms，相邻预览约 80–82ms；这是本次小样本的观测，不作总体速度或质量提升比例承诺。

日常 8081 模型的 PID、创建时间和启动参数在验收前后完全相同（PID 51920），健康接口返回 `status: ok`。临时 8083 模型和隔离浏览器已关闭，日常浏览器和自启注册未调整。
