# 本地小模型：速度和短文本准确性追加验证

日期：2026-11-03。继续使用既有 Hy-MT2-1.8B Q4_K_M、llama.cpp b12069、RTX 5070 Ti；六槽、每槽 2048 上下文。没有下载新权重、调用云端或上传用户论文，前端保持原样。

本轮唯一上线行为是默认翻译模板的网页标题最多取 256 个 UTF-16 单位，截断点避开 Unicode 代理对。普通标题、摘要原 300 单位预算、完整待译正文、官方采样和 1024 输出上限均保持。适配器版本升为 1.0.6；用户自定义 prompt 保留完整标题和原始 `{{context}}` 语义。

## 官方依据与本机核对

[Hy-MT2 官方模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B) 提供单用户翻译、术语、结构和背景模板，并建议 1.8B 使用 temperature 0.7、top_p 0.6、top_k 20、重复惩罚 1.05。模型没有默认 system prompt。本轮未降低温度或改贪心解码来追求速度。

[llama.cpp b12069 官方 server 文档](https://github.com/ggml-org/llama.cpp/blob/b12069/tools/server/README.md) 说明输出 token 上限、prompt cache 和真实 timings。实际执行已安装 `llama-server.exe --help`，核对 `--ctx-size`、`--predict/--n-predict`、`--parallel`、`--cache-prompt`、`--cache-ram`、Flash Attention 与 KV 缓存参数。现服务状态记录确认六槽、总上下文 12288；启动脚本已经开启 prompt cache，未重复增加无证据的缓存设置。

## 实验设计

使用十二个公开地理名 / 合成标签：Akkad、Babylon、Assyria、Sea of Galilee、Kingdom of Mari、17.5 m、Euphrates、Tigris、Mediterranean Sea、A-12、35°N、ZKR-17。

背景为明确标注的合成古代两河流域网页标题和摘要。它并非用户截图的 OCR 结果；截图原始识别文本尚不明确，不能反推译文制造所谓原问题复现。检查侧重预期常见地名、数字 / 代码保留以及有无扩写，不等同于独立人工译质评测。

每种短文本条件用 seed 42 / 77 / 123，轮转模板执行先后，保留真实输出、结束原因、服务 timings 和缓存情况。总计 234 次真实本机调用：108 次短文本模板、108 次输出预算、18 次标题预算。固定 seed 只用于实验，没有写进生产采样配置。

## 结果与取舍

### 保留短标签的消歧背景

| 模板 | 保守词表 / 结构检查 | p50 / p95 | 输出 token 总数 |
| --- | --- | --- | --- |
| 既有标题和摘要 | 36/36 | 40.2 / 62.6 ms | 147 |
| 删除背景 | 32/36 | 37.7 / 50.4 ms | 147 |
| 无背景，增加短标签忠实不扩写要求 | 36/36 | 38.9 / 53.6 ms | 147 |

删除背景时，Mediterranean Sea 三次变成“地中海海”，Tigris 一次偏离预期常用地名写法，说明背景确实可帮助短词消歧。单独增加忠实约束没有超过原模板的检查结果，也没有足够速度收益。因此两者均未上线，不能声称已经解决用户未知原始 OCR 的幻觉。

### 不缩小普通短文本的输出上限

| max_tokens | 次数 | 截断 / 错误 | 与同 source+seed 的1024输出不同 | p50 |
| --- | --- | --- | --- | --- |
| 1024 | 36 | 0 / 0 | 0 | 22.1 ms |
| 64 | 36 | 0 / 0 | 0 | 22.3 ms |
| 128 | 36 | 0 / 0 | 0 | 22.4 ms |

三组均只生成 147 tokens，模型本来就正常结束，缩小上限没有加速实际解码。为避免其他语言、长译名或格式输入被截断，本轮保留 1024。截断输出继续拒绝交付，未把缺字输出当“更快的结果”。

### 为无界网页标题增加预算

原实现已限制摘要，却把完整网页标题直接放入 prompt。合成 12000 字符标题的首见请求，实际评估 1597 个新 prompt tokens、约 172 ms；256 单位标题预算的相关首见请求只需约 68 个新 tokens、约 18 ms。所有标题预算对照仍把 Babylon 译成“巴比伦”。

这些是缓存热度不同的小样本，不能宣称十倍加速；缓存已经热时，差距会明显缩小。可确认的是输入 prompt 被有界缩短，避免超长标题无界消耗每槽有限上下文。256 以内的正常标题逐字不变，并保留消歧背景，没有改成所有 OCR 都无背景。

实现位于 `src/backend/providers/llamacpp.ts`，默认模板调用 `boundedTitle`，Unicode 高 / 低代理对跨边界时退一单位。正文完全不裁剪。自定义 prompt 的附加背景和 `{{context}}` 仍使用原始内容，避免覆盖用户明确设置；其上下文预算仍由用户模板负责。
