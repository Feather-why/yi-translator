# 0.2.3 翻译提速：实现与验收

2026-11-03。实际项目 `项目根目录`，扩展 0.2.3、后台 `0.2.3-performance`、协议 v2。没有写前端源码；保留并集成前端负责人已提交的第 21.1 / 23 节更新。模型服务现以六路运行，端口仍为 8081。

## 建议逐项落实

| 建议 | 本次结果 | 边界 |
|---|---|---|
| 综合模式同服务只翻一次 | 已实现：按本段实际服务和配置共享工作，包括内置失败后共同回落本地，直接 final | 两个真实不同服务仍有快速/精确两档；占位符恢复内部可另有请求 |
| 本地增加并行 | 已真实比较 2/6/8，选择六路；每路仍 2048 上下文 | CPU 默认两路；显式用户并发设置优先；八路长段更慢 |
| 快速优先、放开批量 | 共享逻辑队列 8→32；同优先级 fast:final=3:1；服务限流按实际批量 HTTP | 低优先级后台任务即使等很久也不能挡新首屏；不提高各服务 QPS/额度 |
| 降低复杂格式恢复成本 | 本地按需生成锚点，先保留自然整句，复用真实词典/热对齐；增加匿名频率/耗时计数 | 不用碎片译文拼正文、不跳过标签校验；困难路径最坏可能多一次整句 |
| 悬停预热 | 已接现有前端 `providers:warm`，只唤醒已配置且启用的本机 llama.cpp | 每目标 120 秒冷却、全局限频；敏感/隐身拒绝；不发提示词，不自动下载或常驻保活 |
| 内置翻译做高速档 | 保留已接入的 Chrome/Edge 原生桥接和高速优先顺位，Hy-MT 保留最终档 | 语言包必须就绪、浏览器和语言对必须支持；不可用自动落本地，不假装内置已成功 |
| 前端规则缓存、短动画、提前连后台 | 保留前端负责人已有实现，并接通其预热 RPC | 本轮后端未修改这些文件；单独列最终前端集成实测 |
| 耗时拆分 | 已提供仅管理页读取的匿名 `performance:get`：逻辑排队、实际 HTTP、真实模型计时、恢复计数、共享次数 | 未把全局平均值伪装成逐段耗时；`result.timing` / SSE `partial` 本次仍可选缺省 |

## 固定旧前端的真实网页比较

独立 Edge 临时配置、真实本机 GPU、综合模式、`noCache:true`、固定二十段首屏、固定视口、关闭显字动画，每种三轮。原版前端保持相同，改变后端实现及模型/适配器 2→6 路；这属于组合优化。模型已热，未清 llama prompt cache，不是模型冷启动实验。

| 三轮中位 | 0.2.2 / 两路 | 0.2.3 后端 / 六路 | 整批耗时减少 |
|---|---:|---:|---:|
| 二十短段全部最终完成 | 3028 ms | 1366 ms | 54.9% |
| 二十个带链接/代码段全部最终完成 | 9281 ms | 4700 ms | 49.4% |
| 短段首次最终结果 | 548 ms | 364 ms | — |
| 结构段首次最终结果 | 1474 ms | 981 ms | — |

短段每轮 HTTP 36→20，同源重复归零。结构段新版为 21 / 31 / 21，包含实际格式重试/恢复；不能宣传所有段落永远只有一次请求。每个结构轮保留八十条链接和二十份代码，全部完成且还原 HTML 精确一致。

**首次可见译文有取舍。** 原版先显示 fast 的中位时间为 157 / 504 ms；新版同服务直接 final，首次可见为 364 / 981 ms，较晚约 206 / 477 ms。以上测的是完整译文落到页面，不是模型第一个 token。整屏最终完成变快，不等于最初看到字也都更快。降低首个可见等待下一步应优先用已就绪的内置快译，或单独实现和验证 SSE。

取消后新增请求仍为零、全部在途请求中止；六槽清空约 1007 ms，原两槽约 562 ms。并发增加也增加了取消收尾成本。详见 [PERFORMANCE-VALIDATION.md](PERFORMANCE-VALIDATION.md) 与机器可读对照 `outputs/test-evidence/performance-comparison.json`。

## 最新前端与后端的最终集成实测

另外加载实际 `.output\chrome-mv3`，包含前端负责人第 23 节的规则缓存/动画与预热入口，复用同一 fixture、真实六槽模型和三轮方法。结果单独保存在 `outputs/test-evidence/performance-integrated/`；不能将它与旧前端的受控组混作同一组实验。

| 实际正式包，三轮中位 | 二十短段 | 二十结构段 |
|---|---:|---:|
| 首次最终 / 首次可见完整译文 | 340 ms | 1084 ms |
| 全部二十段最终完成 | 1704 ms | 5085 ms |
| 每轮实际 HTTP | 20 / 20 / 20 | 21 / 28 / 20 |
| 相对最初 0.2.2 整批耗时减少 | 43.7% | 45.2% |

最终正式包在该固定样本中整屏约快 1.78 / 1.83 倍，不能归因于前端某一项，也不能凭它与受控组的差别认定前端变快或变慢。模型生成随机性、恢复调用和缓存热度均会影响结果。新版同服务仍没有 fast/partial，首次可见约 340 / 1084 ms，比原版 fast 的 157 / 504 ms 晚；非模型 TTFT。

三轮结构全部通过八十链接/二十代码、还原与零页面异常；取消六个请求全中止，后续新增零，槽清空约 996 ms。匿名 `performance:get` 实际收到 149 份真实模型时序与一次 lazy 恢复；HTTP 聚合含一次 health 和 149 次完成请求，另有六次取消，与网络观察一致。测试通过 Enter 开始、未悬停，`providers:warm` 被动观察为零，不把本轮成绩归功于预热。

## 显存与预热

三轮独立模型实验中，六路二十长段约 3.60 秒，优于两路 5.48 秒和八路 5.04 秒。独立显存重测峰值：两路 1407.551 MiB、六路 1691.559 MiB、八路 1833.559 MiB；六路约 1.65 GiB，低于 2 GiB。采集的是模型 PID 专用显存，整卡总量包含其他应用。首组三轮的采集器失败已保留 null，不拿它证明预算；修复后独立重测才取得上述数据。

预热在独立临时 8082、sleep-idle=3 秒条件下真实验证：sleeping=true→GET props/slots/props→false，总约 744 ms。slots 只等响应头就取消正文读取，无 POST、无提示词、无缓存或记忆写入。未为预热试验强制让现用 8081 睡眠。脚本仍闲置十分钟卸载，预热限频随本次后台实例保存。

实际正式包的普通非敏感空白页悬停测试也通过：悬浮球实际调用一次 `providers:warm`，模型仅收到一个无正文 GET `/props`，没有翻译任务或 completions。移开再悬停仍只有一次；管理页补充查看返回约 119 秒 cooldown 且无新增 HTTP，确认前后端两层限频。该测试没有强制模型睡眠，唤醒真实性由上一独立 sleep3 实验验证。证据在 `outputs/test-evidence/warmup-browser/`。
