# 后台重复开销优化（0.2.8）

2026-11-04。前端与共享协议不变。仅调整后台读写、状态通知与同步计划。

## 已实现

- `BackendStorage.cacheGet` 使用 readonly 事务，完成后直接返回。访问时间合并最多500ms，256个不同key提前触发；插入触发淘汰前先合并访问时间。同一条目多次访问只写一次元数据，重新读取当前条目再更新时间，不能覆盖新译文或复活已经删除的缓存。重启丢失最后少量LRU访问时间只影响近似淘汰顺序，不影响译文正确性。人工记忆与容量计数路径不变。
- 状态端口按 BackendCore 实例共享一个订阅、一个5秒定时器和一份快照。普通活跃计数等变更100ms合并；初次连接、显式管理操作和核心重要错误即时通知。最后一个端口断开时清定时器/订阅，坏端口不影响其他页面。共享的是序列化前的状态，不共享网页正文。
- 后端敏感域名规则按 storage 实例缓存，一次并发读取供多个判断使用。`settings.ui` 变化立即失效；读取期间有更新则重新读取，dispose后的迟到读取按失败处理，不重新注册监听器。读取失败/非法数据仍按敏感来源处理；隐身无需读取。无变更事件能力的兼容环境仍直接读取，不缓存无法失效的规则。未缓存网页URL、正文或单个网站的判断。
- 同步通知的目标时间不变时不重复落盘和替换alarm。真正改期/配置仍串行持久化，较新停用覆盖较旧计划；失败允许同时间重试。同步进行中的dirty标记仍记录后续变化，额度持久化不参与此节流。
- 综合任务共享TM和每档自动缓存查询由Core同轮实现，详情见`OPTIMIZATION-028-CORE.md`；noCache仍完全绕过。
