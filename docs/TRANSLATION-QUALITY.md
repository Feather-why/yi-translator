# 本地翻译：完整句义与占位符质量优化

日期：2026-11-03。模型仍为已部署的 Hy-MT2-1.8B Q4_K_M，未更换更大权重；前端不改。`llamacpp.ts` 适配器升级为 1.0.3，使旧版本产生的自动翻译缓存失效，用户自定义提示词和采样设置继续生效。

## 原因与真实对照

原有安全降级在两次标签校验失败后，把每个 `<g>` 之间的文字分别翻译，再按源文顺序拼回。它保住了链接和标签，但割裂了 `from one language to another` 等语法结构。原始截图中的英文定义因此出现“来自一个的文本或语音 语言 另一方面”这样的碎片。

同一公开 Wikipedia 定义，在真实本机 GPU 上的对照：

- 原叶子降级：“机器翻译 利用计算技术来实现 翻译 来自一个的文本或语音 语言 另一方面，包括两种语言的语境、习语和实用细节。”
- 新冷对齐路径：“机器翻译是利用计算技术将文本或语音从一种语言转换成另一种语言的过程，包括两种语言的语境、习语和实际运用层面的细微差别。”

后一结果先生成整句，再把 `机器翻译/转换/语言` 的原标签放回对应译词。恢复标签不会改变正文语序。模型仍可能选择不够理想的措辞；这次修复针对上下文被标签拆碎的明确根因，不代表所有译文达到人工翻译质量。

## 降级链

1. 正常整段翻译后严格验证原有标签的编号、数量、闭合和父子关系。
2. 加强要求重试一次，说明标签不是句子边界，应先理解整句，再将成对标签放在对应译词两侧。
3. 仍失败时进入 `translateWithProjectedPlaceholders`：去掉 `<g>`，将 `<x>` 换成唯一的本地不透明标记，如 `[TXP0_0]`。先翻译连贯正文，再投影回原标签。
4. 投影只接受精确锚点、离线词典的精确义项，或已准备好的真实词级语义映射；不能按源文字符比例猜链接位置。
5. 投影不能可靠完成时返回 `null`。核心保留原有最终安全降级，不通过关闭校验、捏造链接或把词级错误当服务离线来隐藏问题。

短词翻译仅为寻找锚点和术语参考，绝不将短词译文按源文顺序拼成正文。最多请求六个独立短词组，每组最多 80 字符；外层包住整段的格式不重复翻整段当术语。

## 冷模型也能处理同义译词

仅用独立词组翻译来找锚点仍不够：`translate` 单独常译成“翻译”，但自然整句中可能译成“转换”。ECDICT 的真实 `translate` 条目含 `[计] 转换`，因此可通过公开离线词典找到这个精确义项，不需要等待 ONNX 下载。

词典只在已就绪时查询，最多八个独立英语单词，每次最多等待 45ms。匹配的是当前完整译文中实际存在的词面，不把不同义项的歧义硬归并。相同译词重复出现时，先排除已定位格式范围，再稳定选取不冲突的相同词面；这仍不保证所有篇章层面的同词消歧都正确。

原子标记必须在译文中各出现一次，不得缺失、重复或更名，最后逐一还原为原始 `<xN/>`。源文本若本来包含同形标记，会递增 nonce 避免冲突。代码、网址等实际内容仍由原页面持有，后台不让模型产生新链接地址。

真实语义词映射仅用于模型已经准备好且队列可用的情况，不能因恢复一个链接等待首次 118MB 模型下载。整句或整段的高亮兜底范围不能当作词级标签定位证据；过宽、交叉、父子冲突的投影会被拒绝。

## 提示与试验依据

官方模型卡提供默认翻译、术语、分隔符和结构化翻译提示，并推荐 1.8B 使用 `temperature=0.7, top_p=0.6, top_k=20, repeat_penalty=1.05`。本次保留采样默认值及单用户消息格式；术语使用官方“参考下面的翻译”形式，正文始终位于清楚的最终翻译边界之后。

真实试验否决了几种表面上合理的方案：结构化大纲、改为常见括号、单个标签重翻，以及只恢复标签的二阶段提示，均会出现丢标记、复制原文或指令泄漏，不能仅凭个别成功样本发布。提示本身不能代替本地严格校验。

来源：[Tencent Hy-MT2 官方模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B)。词典来源及许可证沿用 `B3-DICT-ALIGN.md` 与 `THIRD-PARTY.md`，未增加运行依赖。
