# 占位符校验失败修复与回归

## 复现与原因

2026-11-03 在用户真实 Edge 的 Wikipedia Machine translation 页面复现。部分短标题和正文能够翻译，但出现「翻译结果未通过占位符校验」及后续「请配置至少一家服务」。本机 GPU 服务持续正常推理，没有 OOM 或网络错误。

原因有两层：

1. 1.8B 模型对复杂网页的嵌套链接、引文和原子占位符偶尔丢失标签或改变层级。加强提示可以降低失败率，不能保证任何段落都遵守格式。
2. 原实现把文本格式失败也计入服务连续故障。三段格式失败会触发整个本地服务冷却，使之后原本可以成功的段落变成 no_provider。

此前部署阶段还修过一项提示词边界问题：Hy-MT 把官方翻译模板冒号后的内容全部视为原文，因此标签说明必须放在模板之前，不能跟在原文前面一起被翻译。

## 修复策略

- 保留占位符数量、编号、闭合和平衡校验，并验证父子关系；不以关闭校验或随意补写模型输出的链接来隐藏问题。
- 正常翻译后校验；不通过时加强提示重试一次。适配器主动抛出的 placeholder 错误也进入同一条重试链。
- 两次都失败且源文包含占位符时，将标签留在本机，只翻译标签之间的文字叶子，再用原始标签逐字还原结构。纯标点和空白不请求模型。
- 叶子译文同样校验，取消信号在每个叶子前后生效。仍然失败则按原错误返回或换下一家，不生成虚构链接、编号或地址。
- placeholder/bad_input 不再熔断服务；网络、服务端、限流、鉴权和额度错误才影响服务可用性。状态保留实际错误，冷却时不再用不相关的「未配置」掩盖已知故障。

## 质量与性能边界

叶子降级是格式可靠性兜底。一个长句拆成多个片段可能降低语序自然度，并增加请求数，因此只在完整句子和加强重试都失败后使用。格式仍然完整，所有网址继续由前端从原页面还原。

## 自动测试

执行 `npm run test:backend`，其中 core.test.mjs 包含：

- 模型连续丢失嵌套 `<g>` 和 `<x/>` 后仍能正确本机还原。
- 适配器抛出 placeholder 时也执行重试及降级。
- 多次文本校验失败不会停掉后续正常翻译。
- 原有取消、阶段唯一性、缓存/noCache、强制服务和额度测试全部保留。

首次修复后的完整回归为 112 项通过；随后 B2–B5 的最终汇总以 `docs/BACKEND-ACCEPTANCE.md` 为准。独立浏览器及用户重载后的日常 Edge 验收分别记录如下。
