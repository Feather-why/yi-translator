# B2 混合调度器实现与验收

## 选路

精确档接入 OpenAI 兼容、Gemini 和远程节点，保留本地 1.8B 兜底。新云端服务未配置时不会发送请求，未知免费额度不被当作免费预算。`providerHint` 强制选择指定服务，不自动换成别家。

缓存与个人译文优先。未命中时先过滤停用、暂停、配置缺失、冷却及预算不足的服务；按 EWMA 延迟、最近成功率、额度压力和即将重置的剩余额度打分。用户置顶高于页面粘性，同一页面/档位优先使用上次成功服务；粘性最多保存 500 项、30 分钟有效。

## 熔断与半开

连续 3 次基础设施失败或遇到限流后冷却，30/60/120 秒指数退避，最多 300 秒。鉴权失败等待用户修改配置。到期后只放行一个 HTTP 批次作为半开探测，成功关闭熔断，失败继续退避。

文本占位符与输入错误不计为服务离线；详情见 `BUGFIX-PLACEHOLDERS.md`。

## 首屏对冲

优先级 0、未强制指定服务且机翻/本地服务预算充足时，等待 `max(300ms, 首选 P90)`，仍未完成则调用第二家。首选提前失败会立即切换。先完成者交付并缓存，取消另一份；两份实际发出的请求都预留用量。云端大模型不参与自动对冲，避免重复付费推理。

合批窗口 5ms。字符预算逐段预留，并发与 QPS 只在实际 HTTP 批次执行时消耗，避免腾讯/小牛按每段限速而无法合批。

## 状态

协议 v2 新增可选 `pinned`、`circuit`、`cooldownUntil`。旧前端可忽略这些字段，原有端口与 RPC 保持兼容。远程健康检查将模型、队列和吞吐的真实返回放进节点状态，没有的数据不伪造。

远程扩展适配器每次请求一个段落，避免等待同批最后一段才显示第一段；gateway 本身仍支持多段 NDJSON 批量。

## 验证

1. `node tests/contract/run.mjs` 编译 strict/noUnchecked 后运行全量后端合约。
2. `node --test --test-name-pattern 'B2|对冲' tests/backend/core.test.mjs tests/backend/hedge.test.mjs`：7 项专项通过，覆盖首选及时返回、延迟对冲、双失败、取消、半开唯一探测、页面粘性及胜者缓存/双边记账。
3. 三家新适配器与本机网关的 20 项专项测试通过，实际本机 gateway→GPU 1.8B 的两段请求约 208ms，含嵌套标记。

远程 7B 设备与云端账户未提供，不能据本机 1.8B 结果宣称已达到远程 7B 首段 <1.5s。部署网关、鉴权和协议详见 `B2-REMOTE.md`。
