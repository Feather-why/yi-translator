# 第 34 节：官方账户额度账本

日期：2026-11-04。本文说明 `src/backend/scheduler/quota.ts` 的内部实现与验收；Core 的 DeepL 探测、密钥身份和两层预算组装由集成方维护。

## 需要修复的问题

官方返回的 `character_limit` 不一定等于旧默认的 500,000 字符，也不一定按自然月重置。直接使用普通月账本会在月初误放额度；只向上校准又无法接受新账期的较小用量。探测等待期间还有本机请求，直接覆盖用量可能抹掉这些请求。换密钥后继续沿用同一服务 ID 的计数也会把两个账户混在一起。

## 内部接口

```ts
type QuotaDefinition = Omit<QuotaInfo, 'used' | 'resetAt'> & {
  account?: string;
  windowEnd?: number | null;
};
interface QuotaSnapshot {
  scope: string;
  used: number;
  resetAt: number;
  localSent: number;
}
ledger.snapshot(id, quota);
await ledger.calibrateOfficial(id, quota, officialUsed, snapshot);
```

`account` 只接受小写 64 位 SHA-256 十六进制摘要，由 Core 从当前凭据派生；账本不接触原始密钥。内部计数和发送前日志使用 `id@account`，预留也按这一范围合计。不同账户和原有的本地日/月预算互不影响。删除服务时会清理该 ID 下的所有账户分支和未完成预留。

公共 `info()` 只返回 `QuotaInfo` 的额度、用量、周期和可确认的截止时间，不传播账户摘要、内部范围或无限期哨兵。错误仍以原服务 ID 标识服务，错误文本不含账户摘要。上述扩展不是 RPC 输入，也不修改前端协议。

未指定 `account` 的旧调用继续按原来的日/月周期、设备分量合并和计费方式工作。已指定 `windowEnd` 却未提供账户摘要会返回 `bad_input`。

## 官方账期与校准

未知窗口（`windowEnd` 未提供或为 `null`）使用内部 `Number.MAX_SAFE_INTEGER` 作为截止标记，前端不返回 `resetAt`。跨月、跨年和重启都不会自行清零。

已知的未来截止时间会对外返回。到期后保留现有用量并去掉对外截止时间，等待可信 `/usage` 再定基准；不会凭过期配置猜测下一账期。已有账户的新窗口只能由 `calibrateOfficial()` 确认，旧排队任务所持的配置副本不能把窗口改回去。窗口改变后，旧窗口中已经准备好的发送日志会失效，调用方需释放后重新预留。

`localSent` 是独立、持久的累计本机发送量。探测前取得快照，收到有效官方结果后按以下公式校准：

```text
新用量 = 官方返回用量 + 当前 localSent - 探测前 localSent
```

因此官方用量下降可以生效，同时保留探测期间新增的已发请求。取消但未发送的预留，以及上游“额度耗尽”信号本身，不增加 `localSent`。如果官方统计已经包含探测期间的某次本机发送，短时间内可能保守多计该部分；下一次可信探测可以纠正。这比把尚未入账的发送抹掉更稳妥。

Core 必须丢弃旧密钥、旧配置世代或乱序探测的结果；账本检查快照的账户范围、数值和单调发送量，不负责探测请求的排序。

## 限额变化与发送原子性

账户计数同时持久化最新可信 `limit`。每次查询、预留、准备及最终发送都使用 `min(该请求原限额, 最新账户 limit)`。可信探测可以上调或下调这个值；普通读取和旧任务副本不能恢复旧限额。

例如任务在额度 100 时预留了 10 个字符，等待发送槽期间官方限额降至 0 或 5，最终 `dispatch()` 会拒绝，永久用量仍为 0。即使限额变化发生在预备日志落盘期间，`prepare()` 返回前也会重新检查。可信上调后，新任务能使用新限额；旧任务保守遵守自己的原上限。

账户预算和用户显式设置的本地日/月预算可各创建一份 lease。Core 应将同一次 HTTP 请求的全部 lease 展平，交给同一个账本的一次 `dispatch()`：所有验证先完成，再同步提交全部计数，任一层失败都不会只扣另一层。不能分别提交两层预算。

已有发送前日志和单次存储提交机制继续使用。崩溃后，是否已发出的日志无法确认时会保守记一次，并同时增加 `localSent`，然后清空日志。官方账户即使跨过已知截止时间，也保留这笔恢复用量供后续可信探测校正；重复重启不会重复归账。

## 存储与同步

账户分支保持在本机存储中，普通跨设备合并忽略 `id@account` 分支，避免使用只增计数规则破坏官方校准。重载前先等本机待写入快照完成，再恢复本机账户计数；可以保持校准后的较小用量、最新限额和累计发送量。普通服务 ID 的多设备合并规则保持不变。

Core 仍需把已知官方限额及周期元数据绑定到凭据摘要并持久化。可信官方额度可代替默认展示额度，但用户显式设置的较小预算应作为独立预算保留；不能用 `min(旧默认 500k, 官方额度)` 截断新账户的实际额度。
