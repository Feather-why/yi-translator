## 图片识别复用

`MediaService` 仍先校验并读取实际图片字节，以 SHA-256 内容键复用原始 OCR 文本、坐标和置信度。同 URL 内容改变不会误用旧结果，不保存图片字节或 URL，不写磁盘/同步。最多 8 项，每项序列化不超过 64,000 字符；逻辑有效期 2 分钟，在后续 OCR 请求时清除过期项，**不是到点物理擦除的定时承诺**。最多登记 4 个并发识别合并项。

缓存给调用者独立副本，后续译文或调用者修改不会污染原识别数据。单个等待者取消不影响其他等待者。`noCache` 不读、不写，也不参与在途共享；现有 RPC 对敏感/隐身来源的强制保护继续生效。

使用独立 Edge 测试配置、真实 PaddleOCR CPU 和六行合成标签图，连续两轮结果如下。识别输出逐字、坐标、置信度比较一致；不调用翻译 GPU，不上传用户图片。测试的图片是 900×420 合成标签，不能代表用户地图或所有分辨率。

| 条件 | 第一轮 | 第二轮 |
| --- | ---: | ---: |
| 全新测试配置首次 OCR（含模型准备/初始化） | 86.18 秒 | 29.67 秒 |
| 同图缓存再次读取 | 4–7 ms | 4–5 ms |
| 引擎已热，显式 noCache 重新识别 | 1.37 秒 | 1.39 秒 |

首次成本很大且波动，复用只改善重复图片请求。测试使用本地已校验权重，额外网页网络记录没有捕获 offscreen 内部阶段，因此尚不能把首见耗时精确归因于下载、ONNX 初始化或图优化；不据此声称首次识别提速。SDK 已默认识别批量 6，未盲目加大并发、降低分辨率或切换 GPU 来损失质量/争抢翻译资源。

复现：`node tests/backend/ocr-reuse-real.mjs`；可设置 `BROWSER_EXECUTABLE`、`OCR_MODEL_CACHE` 和 `REPORT_DIR`。原报告在交付副本 `test-evidence/followup-ocr/result.json` 与 `followup-ocr-trace/result.json`。

## 同批阅读顺序

`OrderedDelivery` 仅用于含多个 paragraph/sentence/pdf 段的任务。模型仍并发执行，后段完成后最多等前段 250ms；前段已有快速结果、最终结果或错误后，后段即可显示。超过窗口允许后段显示，避免整页被一个慢段长期挡住。选择翻译、字幕和 OCR 标签即时交付。

未显示的快速结果可被最终结果替代，但等待期限保留首次完成时间，不重新开始 250ms。取消、同 ID 任务替换、端口断开清理缓冲；`job-done` 在待交付结果之后。时间基准使用单调时钟。它改善临近完成的局部乱序，可能增加后段最多约 250ms 的可见延迟，**不增加吞吐，也不保证整页严格从上到下**。前端一次发送的段顺序必须符合阅读顺序；跨任务视口排序仍需前端管理。

PDF 的主要漏译原因是物理第 13 页（印刷页码 x）的目录 References 项误触发全局参考文献截止，导致后面 89 页可翻译文本被过滤；真正参考文献在物理第 87 页（印刷页码 70）。论文每页都有文本，不是“后半本都是扫描图片”。普通阅读器文本路径的此问题与后端扫描 PDF 上传限制无关。

另确认：目录多行被合成段落后有的被跳过、有的整体翻译破坏行/页码对应；致谢正文被误居中；日期与署名原本两行合成了一个窄框。当前证据支持“两行合并”，没有声称已复现两个物理页被后端合成一页。修复必须保留原页号、独立目录行、原有行界及可靠的居中判定。

## 本地小模型实验

[LOCAL-MODEL-FOLLOWUP.md](LOCAL-MODEL-FOLLOWUP.md) 记录官方依据、全部条件和限制。沿用 Hy-MT2-1.8B Q4_K_M、llama.cpp b12069、GPU 六槽 / 每槽 2048、已有 prompt cache。没有下载更大模型，没有上传论文，没有改成极低温度或牺牲占位符校验。

- 12 个公开地名/合成标签 × 3 seeds × 3 模板，共 108 次：旧背景模板检查 36/36，直接删背景 32/36。删除背景会使部分地名更差，未上线。
- 输出上限 1024 / 64 / 128 的 108 次：同条件输出相同，无可测提速，保留 1024。
- 标题预算 18 次：无界长网页标题可消耗很多 prompt tokens。只给默认模板 title 增加 256 UTF-16 单位预算，截断避开代理对；完整待译正文不裁剪，普通标题和摘要保持，用户自定义 prompt 保留语义。

这些是小样本、词表和格式检查，不等同于对所有网页翻译质量的人工评分。地图真实 OCR 字符串未知，不能把合成地名实验当成地图误译已修复。旧六并行、综合模式同服务去重等已在 0.2.3 上线，既有基准见 [PERFORMANCE-REPORT.md](PERFORMANCE-REPORT.md)。
