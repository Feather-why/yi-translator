# 0.2.5：量化精度、标签语义与划词速度复核

日期：2026-11-03。正式扩展 0.2.5，后台 `0.2.5-semantic`，协议 v2，llama.cpp 适配器仍为 1.0.6。本轮只改后端、后端测试和文档；前端保持原样，日常浏览器体验由用户测试。

结论：**保留现有 Q4 模型，把已验证收益的嵌套标签恢复和对齐计算优化上线。** Q6 在新的小样例集没有稳定质量优势，六槽显存只余约32 MiB；Q8 超出原2 GiB目标。没有编辑权重、降低采样质量、删正文或放松占位符校验。

## 量化对照

使用腾讯[官方固定版本](https://huggingface.co/tencent/Hy-MT2-1.8B-GGUF/tree/a0c709d9fac510f2c807aa3af52872340dc37a4a)的 Q4_K_M、Q6_K、Q8_0，三份文件重新核对完整 SHA256。Q6 为本轮新下载的研究文件；现用8081服务、模型路径和六路参数不变。

推理前冻结8个新场景、4个已见回归，每模型两种seed，合计72次质量请求。另有Q4/Q6各20段×2轮六并发，共80次资源请求；6次预热另列。48个新场景输出去重为38项，隐藏模型、seed及耗时后分给两个AI评审者；评分冻结后才合并身份。**这是AI盲审，不是人类评审；实际只有8个不同新source，不能把48输出当作48道独立题。**

| 指标 | Q4_K_M | Q6_K | Q8_0 |
| --- | ---: | ---: | ---: |
| 新样例正文主口径 | 12/16 | 11/16 | 10/16 |
| 严格实体完整性口径 | 11/16 | 11/16 | 10/16 |
| 新样例标签结构通过 | 4/4 | 2/4 | 2/4 |
| 热GPU、无prompt缓存，单请求中位数 | 226 ms | 240 ms | 286 ms |
| 六槽专用显存采样峰值 | 1689.6 MiB | 2015.6 MiB | 2425.6 MiB |

严格口径把Q4一条“探头”弱化成“监测数值”的边界译文判失败。更高精度未稳定修复重复确认、引文指向和词义混淆；表内小差异不证明Q4总体更准确。Q6批次少生成约8%的tokens、耗时也波动，不能拿它的批次时间声称吞吐更高。Q6仅比2048 MiB低32.4 MiB，1秒显存采样还可能漏过短峰值，因此不默认切换。

所有质量请求使用相同提示词与采样、配对seed；服务统一六槽、每槽2048上下文。模型顺序固定Q4→Q6→Q8，未交叉随机化；全部`cache_n=0`。原始单次输出没有经过插件重试/修复，失标率不能直接当成最终插件失败率。详细哈希、方法、评分、敏感性和资源结果见 [QUANTIZATION-FOLLOWUP.md](QUANTIZATION-FOLLOWUP.md)。

## 嵌套标签恢复

新路径仅面向本地、prompt标签适配器、合法且可消歧的嵌套g结构：

1. 先翻译完整可见正文，g结构保留在本地，x原子用本次专属标记保护。
2. 能用唯一词面/词典/已有锚点恢复时，省掉额外对齐。
3. 局部嵌套父子节点要求独立短语证据，不能仅因XML平衡就把链接包到无关的“王朝”。
4. 先确定子短语，再让父短语沿用已有后代译法，避免“铜印”和“青铜印章”相互冲突。必要时最多再翻一次带一致术语的完整正文。
5. 普通单链接、平级链接仍走原来的一次带标快路；同词出现在不同嵌套上下文时不启用新的先投影与子→父术语强化，保留旧带标路径。不可解决的结构保留既有安全退路，但不声称其自然程度有保证，也未解决所有多义词问题。

只对受影响的自动翻译缓存增加恢复策略revision；用户手动译文记忆保留。实际请求仍经过原调度、限额、取消、综合模式去重和noCache保护。没有把语义标签检查推广成每个普通段落的额外模型调用。

冻结旧0.2.4编译产物，与最终候选各测6个已见公开/合成例×2seed×2条件，共各24个完整Core任务。两条件分别为词典已就绪但无对齐模型、真实E5 CPU已预热。使用同一Q4、隔离8083、单槽2048、关闭prompt缓存，逐响应确认`cache_n=0`。这些条件与上面的六槽量化试验不同。

下表为每种条件两个seed的中位数。它不是全网页、OCR、DOM动画或首次模型加载时间。

| 场景 | 条件 | 旧→新耗时 | 每段HTTP旧→新 |

| Sealand嵌套称谓 | 无对齐模型 | 602→263 ms | 5→3 |
| 安装指南与原子标记 | 无对齐模型 | 666→283 ms | 5→3 |

| Sealand嵌套称谓 | 热对齐 | 507→262 ms | 3→3 |

| 铜印/石印、长父链接与编号 | 热对齐 | 1314→715 ms | 7→5 |

12次嵌套任务HTTP合计78→44，减少约43.6%；12次普通/平级对照的译文逐字相同、请求次数未增加。全部24任务结构校验通过；12条新嵌套输出逐项复核了动作顺序、编号、父子范围与句子完整性，无叶子拼接降级。`Country of the Sea`内链对应“海洋之国”，未包“王朝”；安装指南保留先关闭编辑器再复制的顺序；文物案例保留青铜印章移动、石印留在原处的区别。

“石印封印”“严格按照印刷的那样”等措辞仍生硬，不能宣称模型达到普遍流畅。也不能把78→44请求推导成全站相同比例提速。普通对照的几十毫秒波动未解释为优化收益。

固定顺序先旧后新、每项只有两种seed，未估算统计显著性。以上已见样例用于工程调试，原pilot的holdout-03已经不再是未见留出集。第一次候选在该例热对齐下从7请求退化到14请求并拼出碎片句，被真实测试拦下；失败数据单独保留，没有发布。第二次候选用子→父一致术语修复，才得到上表结果。另有独立审查用同词bank的河岸/银行反例补充歧义保护。

复跑工具：`tests/backend/nested-projection-real.mjs` 与固定 `nested-projection.fixture.json`；通过`PROBE_BACKEND`指定冻结旧编译目录，`PROBE_CONDITION=before`为历史组，`LLAMA_URL`指定独立服务，`REPORT_DIR`指定输出。关键语义护栏不能代替逐条审阅。主交付证据含 `before.json`、`after.json`、`candidate-v1-failed.json` 和 `summary.json`。

## 划词对应与计算耗时

对齐本身保持原有真实词对、引用边界和句子范围规则。改动集中在：

- 只在模型失败/超时后计算备用词典匹配，不在正常首次对齐前重复查一遍。
- 同一次长段对齐内部，对完全相同文本与语言的窗口复用向量；请求结束即释放，不跨请求保存，noCache仍隔离。
- 普通/严格缓存按本地或远程来源、词典就绪阶段隔离；配置变化或dispose后，迟到初始化/推理不会回写新状态。
- 同一真实本地工作合并重复的等待请求；保留严格投影与普通结果的独立快照，不为提速假定过滤总是幂等。

固定真实q8 E5 CPU前后五例，完整tokens、links、spans对象相同。Phonetics首次198.8→175.4ms，词典调用122→61；引号/整句/嵌套可见文本等普通例约19–24→17–20ms。40个完全重复句的测试编码80→2次、287.8→21.5ms，**此大收益只适用于重复窗口，不代表普通页面都有十多倍提升**。已命中缓存仍约0.03–0.35ms，没有可宣称的新加速。完整条件见 [ALIGNMENT-PERFORMANCE-FOLLOWUP.md](ALIGNMENT-PERFORMANCE-FOLLOWUP.md)。

这些缓存修复避免错误来源或旧词典阶段结果被复用，但没有证明任意单词都能零错配。整句连续强高亮仍依赖前端消费现有`AlignResult.spans`；旧前端只联结词token时，后端不能让它自动画连续整句。此次未改前端。
