# 句子与词对应范围修正（0.2.2，2026-11-03）

本次只修改后端对齐算法、服务、offscreen 推理及后端测试，不修改前端。

## 真实问题与原因

用户在公开的 [Phonetics](https://en.wikipedia.org/wiki/Phonetics) 首段选中 `concerns`，中文却只高亮逗号。日常 Edge 已复现；用本机 Hy-MT2 对完整段落生成另一份自然译文，也能在旧算法精确复现 `concerns → ，`。

0.2.1 为了让选中整句时有连续高亮，对没有语义链接的词按句内比例补了位置链接。源、译文长度和语序不同，这种补齐会造成 `concerns → ，`、`are → 们`、`the → 馆` 等错误。它不是可靠词对齐。本次删除全部这种位置补齐，而不是换一个比例继续猜测。

还有两个放大问题的原因：

- 现有前端会缓存第一次 `align:get` 的 Promise。模型的 `loaded` 标志为 true，不代表当前整个段落已经计算完成。原先已热时 280ms 的预算会令慢段落返回空降级，而前端随后永久复用这个第一次结果。
- E5 的双向互为最近邻会漏掉某些正确词组。`研究` 最相近的源词其实是 `concerns`，但 `concerns` 的向前候选很接近，单纯要求双向都第一会丢掉这条语义边；少数语义枢纽词还可能吞掉多个专业术语。

## 当前实现

1. **不再制造位置对应。** 正常结果、冷启动降级和标签投影都不补比例链接。未知词保持未连接。
2. **词与标点不混连。** 字词不能连到逗号、句号等；同类标点可以确定性归一，例如 `.`/`。`、`,`/`，`/`、`。英语省略冠词和常见虚词受中文义项约束，不能因为向量相似就贴到“馆”等实词上。
3. **只扩展有差距的语义边。** 保留有区分度的双向匹配，并接受清晰单向语义差距的词组连接；单向余弦最低 0.35、第一/第二候选差距至少 0.02。完全并列的未知候选不连接。阈值是当前模型的工程取舍，不代表人工校验或概率置信度。
4. **词典消歧优先于贪心占位。** 保留 `auto` 拉丁词的 ECDICT 锚点，词义必须实际出现在对应目标句中。形容词/副词可去掉语法后缀“的/地”。先固定 `auditory → 听觉` 等唯一义项，再为 `acoustic` 的“声学/听觉”消歧；已有模型证据优先。重复术语不能只按出现顺序分配，必须有该次出现的语义支持。
5. **每个未缓存段落给真实结果有界等待。** 前台 `align:get` 未命中缓存时最多等待 5 秒，模型冷/热都适用；一旦结果完成立即交付，不固定等待五秒，缓存仍立即返回。超过预算或失败才返回字面/词典可证锚点，不等待冷词典九秒导入。首次下载超过五秒时，未知词可能没有强高亮，不能把它说成已经正确对应。
6. **继续限制范围与资源。** 按 UTF-16 分句，处理英文缩写、小数、中文引号及句末引用编号；一对多/多对一句组单调配对；模型按句及短窗口执行，过滤跨句边；后台预计算上限 32，前台优先，配置变化不写回旧缓存，闲置释放与推理串行。

句组选取仍有长度启发式，不是另一个模型校对。复杂重排、漏译或句数变化仍可能影响准确度。

## 标签投影接口

`AlignmentService.projection(pair, timeoutMs = 350, options = {noCache:true})` 保留原签名：冷模型或关闭时直接返回 `undefined`，不因标签还原触发首次下载；只用已热本机模型和词典语义锚点。默认 `noCache:true`，明确设为 false 才读写专用 raw 缓存。排队超时任务被取消标记，已进入 ONNX 算子的计算不能中途终止，但随后不会作为成功投影交付。

`align:get` 的 v1 请求、字符偏移和返回结构保持兼容。所有返回 token 仍是实际字词区间，没有把整句伪装成一个词来规避问题。

## 回归与真实模型结果

```powershell
npm run test:backend
node --test tests/backend/align.test.mjs tests/backend/align-sentences.test.mjs
$env:ALIGN_MODEL_CACHE_DIR = 'work/align-model-cache'
node tests/backend/align-correctness-real-model.mjs
```

对齐专项 **21/21 通过**，覆盖字符偏移与分句、跨句噪声、长段窗口、`auto` 词典、前台优先、投影隐私/超时，并新增以下实质约束：

- 未知词不能按位置生成链接，`concerns` 不能连逗号，冠词不能连“馆”。
- 首次模型在等待窗口内准备完成时，RPC 返回真实对应，不锁定冷降级。
- **已热模型 + 新段落推理 350ms** 仍返回真实词链接，不能在 280ms 提前交付空结果。
- 有语义差距的单向词组可恢复；完全相同的未知候选不猜测。
- `acoustic/auditory` 通过真实义项消歧；重复术语无模型支持时不硬分配。

`tests/backend/align-phonetics.fixture.json` 包含用户给出的公开段落、真实本机模型译文及旧错误记录；另一变体使用日常 Edge 中实际较短译文。复用同一固定修订的 E5 q8 和真实 100,000 词 ECDICT，经 ONNX Runtime CPU 验证：

| 实测 | 结果 |
|---|---|
| Phonetics 完整长译文 | `concerns ↔ 研究`，不含逗号；`acoustic ↔ 声学`、`auditory → 听觉`，不扩为整列专业术语 |
| 用户 Edge 较短译文 | 相同关键词双向断言通过，句子链接严格限制在对应句内 |
| 三句日常段落 | `dog → 小狗`，没有 `the → 馆` 或 `are → 们` |
| 重复专业术语段落 | 单词、词组连接不跨句 |
| 超过旧 254-token 限制的长段 | 按句/窗口执行，字符偏移仍相对整段 |

原始报告为 `work/alignment-correctness-real-model.json`。本机短样本约百毫秒，具体数值以报告为准；CPU 结果不能冒充浏览器 WASM 延迟。

最终 CPU 五组约 180/94/24/19/291ms。另用独立 Edge 加载正式生产后台，真实本机 GPU 生成该公开段落的译文，真实浏览器 WASM 执行固定权重，**8/8 浏览器断言通过**：首次前台 `concerns → 研究`、热词/反向 `研究 → concerns`、`acoustic ↔ 声学`、`auditory → 听觉`、第一句双向范围不跨句。九个原链接和精确 HTML 还原、零错误也通过。首个前台请求约 351ms，恰好超过旧 280ms 预算，证明此轮修复了“模型热但当前段未算完”的实际问题。

该浏览器测试权重已缓存、未显式预先调用 `align:init`，不能据此宣称首次公网下载也在 351ms 内。完整原始截图及结果随 `phonetics-stage-final` 交付证据保存。

不再用“填满了多少字符”代替正确率。完整选句会合并该句内有证据的词组范围，但可能存在未连接的虚词或术语。此轮两个真实 Phonetics 译文的目标字符覆盖约 87%/93%、源端约 77%，这些空缺被保留，没有用位置链接涂满。

## 不改前端的边界

前端会固定绘制整个 part 的 `tx-link-soft` 浅底色，段落模式下仍是整段；这层浅底色无法仅靠后端去掉。后端改善的是 `tx-link` 强高亮的语义与范围。

现有前端也不读取置信度或“仅句级”标志，因此不能在不改前端的同时把一句话伪装成有置信度的单词对应。模型不可用、超时或词义不确定时，可能只看到原有浅高亮；本次选择不显示假的词对应。彻底调整浅底色、增加加载提示或刷新第一次 Promise，需要另行前端工作，不在本次后端改动中擅自处理。
